# Prototype investigation contract

This is a generic supervised RCA prototype. Incident-specific gold labels, R3 document-arrival schedules and original charts do not enter the engine.

Intake identifies the event, terminology and relevant specialist tags. Specialists propose conditional mechanisms for a scoped focal condition. The lead reviews/merges proposals and approves immediate evidence needs. The evidence service searches the current collection, assesses coverage and posts remaining questions to the user. Assessment proposes source-linked judgments and causal links. The lead commits structurally valid model proposals and assigns supported conditions for upstream investigation. Independent queued work continues while a question waits. A written answer or uploaded document changes the evidence revision and schedules reassessment.

Physical model judgments remain pending human review. Model-supported is not human-approved. Human approval is a separate local action, never inferred from model text. Reference integrity and source freshness do not establish causal truth.

## Atomic graph update contract

Records are nodes, edges or evidence requests. IDs, kinds, scope keys and claim text are immutable under revise. Edge endpoint membership and all/any mode are also immutable under revise. Endpoints are interpreted as sets, so reordering alone is not a different relationship. A real premise/end-point/mode/proposition change uses replace: a new record ID, replaces=old ID, expected_version=old version. Replacement and retirement of the old record occur atomically; old history remains inspectable. Failure of any operation rejects the complete batch with explicit feedback. No partially applied chain is left behind.

Replace retires the old record and records superseded_by. Referencing a retired endpoint is rejected. Replacement of a node with live dependent edges/requests must also revise/replace those dependents in the same batch; otherwise the batch is rejected. Earlier human approval never carries over to a changed judgment or replacement. Request field/window refinements may be revised with a reason; changing its asset or underlying purpose requires replacement.

Each committed record pins cited source versions. A corrected document marks dependent records stale, propagates to dependent edges, resets human approval, and queues assessment. New independent evidence does not automatically withdraw earlier findings. Source corrections never invert judgments automatically.

## Evidence and run boundaries

Sources are data, never instructions. Written user answers have explicit testimony/availability provenance. Upload receipt does not itself mean a need is answered. Search miss is not proof of unavailability; only an explicit availability response may block a route. Questions are stored for the user, not sent to third parties. Questions with equivalent acquisition scope should share a record while hypotheses remain distinct. Mechanical matching catches exact normalized overlap, not every paraphrase.

A request needs its target, immediate relevance and information that would support/challenge the candidate. Lead approval moves it from proposed to searching. The evidence worker is allowed to update coverage, not manufacture physical causal findings. Search queries, returned documents, model requests, responses and controller feedback are saved.

There is no investigation-wide question quota. A per-invocation model-call budget is an operational pause, never a causal stopping rule. Identical completed work at unchanged source/ledger versions is not reissued. The lead must state waiting/partial when no justified ready work remains. A failed API call preserves artifacts and stops; it is not scored as a reasoning failure or silently rerun.

## Implemented scope

Local CLI and localhost evidence-inbox UI; JSON/text/Markdown/PDF text extraction; lexical full-collection search; GPT-5.5 medium; persisted queue, sources, ledger and audit events. Scanned-image OCR, live internet reference search, enterprise document connectors, multi-user authentication and production deployment are outside this first prototype. The R3 acceptance uses authored surrounding records and a disclosed human-operated fixture respondent; no synthetic reply is presented as a real historical observation.

An identical valid revise is an idempotent no-op, preserving its version and human-review state. It does not abort sibling changes. An explicit operator reapplication of the last rejected lead response is allowed only when its original input ledger and source revision are unchanged; the saved response and original rejection remain preserved. No new model answer is generated by reapplication.

Human rejection marks dependent judgments stale; attaching an existing source to a new question schedules assessment without creating independent corroboration. Pending assessments for one case are coalesced across submitted documents; evidence-worker scopes remain distinct.

## Upstream stopping review

Before stopping with supported causal premises, the runtime schedules an explicit lead origin review for each unreviewed current premise/evidence revision. The lead records whether it is explained, needs scoped specialist work, is blocked, or is context/out of scope. These dispositions are currently in the saved decision text, not mechanically verified semantic labels. Review completion does not certify causal coverage. New evidence reopens review; unchanged evidence does not produce an automatic review loop.
