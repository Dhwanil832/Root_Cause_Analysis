# R3 investigative evaluation v1

Status: evidence package and evaluation specification frozen before new model runs. The current runtime is archived as an **as-is baseline**, with known review findings. A four-way model run has not been performed or certified ready. No historical or prototype result populates the new scores.

## Question and scope

For the same R3 incident, how much expected RCA output does each configured model produce at each investigative stage (a) from correct reviewed preceding inputs and (b) when operating the persistent harness on its own previous outputs?

Four cells: GPT-5.5 clean, GPT-5.5 connected, Qwen clean, Qwen connected. Plan three fresh repetitions per cell, reporting every repetition and mean/range. Repetitions are repeated runs of one developed case, not independent incidents or a generalization study. No best-of selection. This preparation authorizes no model execution.

There are 12 logical stages, eight binary criteria per stage, 96 stage opportunities per run. These are not 96 independent facts: later stages deliberately test preservation/transformation of earlier content. Stage S12 preserves the prior eight-item final-board measure. The earlier 34-meaning pad is retained as background and is not silently used as this denominator.

## Evidence package

All 17 existing JSON records are byte-identical to the R3-INT-01/U05 copies. Initial inputs are D01/D02/D04/D15. The remaining 13 records are held by the fixture custodian. Original chart and evaluator references stay private. Tags, measurements, revision history and surrounding records are authored synthetic premises; the historical chart itself does not verify those invented measurements. The original chart retains unanswered clearance/keeper questions and identified, unvalidated actions.

The fixed quantitative expectations are 390–410 cm3 / 100 cm2 = 39–41 mm yoke displacement and [39,41] minus [-1,1] = [38,42] mm relative withdrawal. The 30 mm primary threshold is exceeded. The specific dynamic keeper path remains unknown. No expected organizational root cause is invented where the package does not establish one.

The documents contain explicit equipment rules and evidentiary cautions. This evaluates applying supplied rules and managing an investigation. It does not independently measure extraction from raw drawings/video or discovery of unknown machine physics. B0 is the only main scenario. No corrected motion record or counterfactual is injected into this comparison.

## Clean-input mode

`clean/index.json` defines 17 independently reset packets covering all 96 criteria. Some stages have separate domain or availability tasks. Each packet has a matching reviewed preceding state and the actual harness packet fields: incident, assignment, ledger, sources, proposals, prior-call context, queue and feedback. Effective role prompts and output schema are frozen.

One completion per packet per repetition. Outputs never seed a later clean packet. No retries to improve content, corrections, or cross-model answers. Clean packets contain legitimate correct predecessor findings, not private criteria or the expected response to the current task. In S07 and S12, correct preceding judgments are necessarily inputs: those tasks test composition and retention, not independent rediscovery of every fact. The introduced duplicate specialist proposals in S03 test merge/review behavior and are explicitly documented in its private rubric.

Clean records remain pending human review in the harness format; authored correctness does not impersonate a human approval. Save raw model output, structural validation and any committed result separately. A correct meaning in a rejected response still earns raw semantic presence credit; loss from committed state is separately recorded.

For clean S12, score the newly emitted account or explicit retained-record discussion; merely being present in the input ledger earns no reporting credit. In connected S12, score the terminal model-produced ledger plus final account. This distinction reflects isolated reporting versus accumulated investigation retention and must accompany the comparison. In all other clean stages, do not award a point solely because its answer already appears in a supplied predecessor record.

## Connected mode

Start a new empty case per model/repetition with the same description and four initial records. Use the same frozen role prompts, schema, controller, retrieval and scheduler for both models; only the provider adapter differs. Do not inject clean states, gold graph, expected IDs, unvisited stages or repaired model outputs. The actual runtime carries ledger, outstanding proposals, recent decisions, sources and feedback forward. It does not forward every historic raw response, and this test must not claim that it does.

The frozen custodian policy in `custodian-policy.json` responds to actual registered relevant requests at a paused evidence boundary. Identical request meaning receives identical records regardless of model, spelling or request ID. Broader requests may receive several relevant documents. No correct hidden record is supplied just because the evaluator wants its conclusion. One D13 unsolicited delivery occurs at the first actual custodian-response batch in every connected arm. Its role is to test handling a useful user-supplied document.

No model generates custodian answers. When no matching record exists, use the fixed package-availability template, citing package scope and never historical nonexistence. Model-blinded operator mapping should be used where practicable; log operator identity, model visibility, verbatim request, matched route, returned documents and unmatched fields. Disclose unblinded operation if blinding is not feasible. Ambiguous new routes go to adjudication before delivery; never secretly invent evidence. This policy is a frozen specification; an automated broker is not implemented by this package.

Calls run in batches of 12, resuming unchanged state. A 96-completed-call ceiling per connected repetition is an operational ceiling, not a valid causal stop or question cap. Mark a reached ceiling as resource-censored. Transport, invalid serialization and adapter/context failures must be classified separately from causal reasoning. No silent input truncation. Known malformed outputs get no semantic repair; save the literal answer and classify their actual effect.

If a resource/transport stop prevents further stage opportunities, mark those rows Harness blocked with the Resource/Transport failure origin; keep completed stage results but do not publish a complete comparable aggregate. An invalid model operation with adequate input/output opportunity is a model-contract failure, separately flagged, not automatically a harness defect. A harness rejection of an allowed valid operation is a harness defect. The clean/connected gap can reflect acquisition, context, routing and error accumulation together; it is not by itself proof that model reasoning alone caused propagation.

## Align stages by opportunities, not call numbers

S01: initial intake output. S02/S03: initial investigation cycle before the first custodian delivery, including relevant specialist proposals and lead handling. Equivalent work performed by another role receives semantic credit; missing a named specialist call alone is not a reasoning failure.

S04: first acquisition coverage decisions before and after the motion document is supplied. S05: first completed assessment/review cycle with D07 and witness evidence. S06: first completed assessment/review cycle with D05/D08. S07: first lead board update after that physical assessment. If several records arrive together, logical checks can map to the same cycle; do not force artificial role calls.

S08: first upstream investigation cycle for each established valve/no-block/contact condition. S09: first coverage/assessment cycle receiving each relevant maintenance/availability record. S10: first assessment/review cycle with the current geometry, recovery, bench and action evidence. S11: final agenda/stopping decision. S12: final active ledger plus the final readable account.

A cycle ends at the first reviewing lead decision after the relevant worker output. Use all relevant output within that bounded cycle, not the best later answer. If the lead performs the assessment directly, that lead decision ends the cycle. Save exact cycle start/end and artifact paths before grading. Later recoveries are reported separately. If prerequisites were never obtained because the model failed to investigate, assign `Not reached` (zero end-to-end coverage) and label acquisition/routing as the failure origin. Do not call an unexposed downstream stage a direct reasoning failure. Harness/infrastructure inability to present the opportunity is `Harness blocked`, which prevents a completed comparable score rather than silently shrinking the denominator.

## Scores

Primary requested score: number of expected meanings/actions present / eight per stage; sum /96 per run. Each criterion is 0 or 1, with accepted semantic equivalents and unacceptable substitutions fixed in `criteria.json`. Extra findings earn no additional primary points. Generic knowledge may justify conditional hypotheses, not unsupported incident confirmations. Citing a document, repeating a task, or naming a topic without its necessary relation/scope is not presence.

Coverage and contradiction are separate. A correct expected meaning somewhere in the designated output receives presence credit even if another passage contradicts it; flag that contradiction and its location. Also report consistent-correct coverage, requiring presence and no material contradiction. This preserves the user's requested meaning metric without disguising mutually inconsistent conclusions. Unsupported extra claims are recorded separately and do not silently subtract arbitrary primary points.

For each scored row save outcome, exposure, exact output location, excerpt or missing-output rationale, contradiction status, and failure origin. `Present`, `Missing`, `Not reached`, and `Harness blocked` are distinct. Blank is unscored, never zero. Scores are displayed only when every row in the denominator has the required review fields. A harness-blocked stage is not a completed score. Never publish a higher percentage by removing failed/unvisited stages.

Also record raw versus committed expected content, valid/rejected operations and reasons, lost/recovered meanings, unnecessary repeated acquisitions, and first-error/later-dependency paths. A raw correct answer discarded by the runtime is a preservation failure, not lack of model knowledge. A structurally accepted wrong claim is not harness proof of truth. Additional claim flags are diagnostic; no all-output precision rate is claimed without exhaustively annotating all claims.

Model names should be hidden during semantic grading where feasible. Every non-credit or contradiction needs an excerpt or bounded absence reference. A second reviewer should adjudicate disputed relationship/scope checks; if unavailable, disclose single-assistant unblinded judgment. Never use GPT's output or the prior 7/8 score as ground truth.

## Freeze and readiness

Package files, criteria, clean packets, effective prompts, input schema, record hashes and current runtime archive are content-hashed. Results belong outside the frozen package. Any change to expected meanings or evidence after model execution requires a new evaluation version and preservation of old results.

The live prototype has no integrated Qwen provider yet. Its duplicate-work signature suppresses changed-focus tasks with identical tag/targets at unchanged evidence. See `REVIEW.md` and the reproduced probe. Those issues require an explicit pre-run resolution, adapter/context qualification and a common versioned runtime lock before four-way execution. Freeze of this evaluation is not a claim that the current runtime is fault-free or ready to compare. Fixes to the runtime must be common to both model arms and frozen before either starts; do not tune prompts or truth criteria to observed results. The original as-is snapshot remains available for traceability.

The archived prototype is source evidence, not a relocated launcher: its original prompt loader depends on the original directory layout. Execution must use the locked effective prompt files or a qualified installation preserving that layout, and verify identical prompt hashes before both providers. Future runs must not silently lose inherited prompt text by launching the archive in a new location.
